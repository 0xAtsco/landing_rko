# E02: локальная операционная памятка

Бот хранит конфигурацию E02 в SQLite. После первого запуска запись создаётся в статусе `draft`; даты и ссылки из окружения используются только для начального заполнения и больше не являются источником правды.

## Пользовательский маршрут

`/start` → два вопроса → набор материалов → проверка подписки на канал → полная инструкция → карточка главного эфира. В карточке доступны регистрация, возврат к материалам и вопрос команде. Оплаты, тарифов, рассрочек и продающих CTA в E02 нет.

Для строгой проверки нужны `VC_PLAYBOOK_SUBSCRIPTION_REQUIRED=true`, `VC_PRIVATE_CHANNEL_CHAT_ID` и invite URL. Бот должен оставаться администратором канала. При ошибке Telegram инструкция не выдаётся, пользователю предлагается повторить проверку.

Регистрация сохраняет исходные source, payload, campaign, post и ветку. Повторная регистрация обновляет только данные Telegram-профиля и не создаёт новую запись. Для будущих точек создаются отдельные задания `24h`, `3h`, `15m` и `start`; уникальность обеспечивается по событию, версии, пользователю и типу доставки.

## Команды команды

- `/webinar_status` — текущая конфигурация и метрики E02.
- `/webinar_reschedule ДД.ММ.ГГГГ ЧЧ:ММ` — создаёт подтверждение переноса. После подтверждения увеличивается версия события, старые будущие доставки отменяются, создаются новые и ставятся уведомления о переносе.
- `/webinar_phase draft|registration|live|replay|closed` — меняет фазу.
- `/webinar_join_url <url>` и `/webinar_replay_url <url>` — сохраняют ссылки; `-` очищает значение.
- `/webinar_support_chat <chat_id>` — назначает чат команды для карточек обращений; `-` возвращает рассылку администраторам.
- `/webinar_notice` — вручную ставит уведомление о текущей дате всем зарегистрированным.
- `/support_queue` и `/ticket <номер>` — очередь и карточка обращения.
- `/material_verify [material_key]` — повторно проверяет Telegram `file_id`, не загружая файлы повторно.

Карточка обращения содержит пользователя, источник, тему, ветку и текст вопроса, а также кнопки «Взять», «Ответить», «Закрыть». Ответ команды отправляется пользователю из бота и сохраняется в SQLite.

## Материалы и откат

Статусы Telegram-файлов: `ready`, `missing`, `invalid`, `unverified`. Невалидный `file_id` не используется при выдаче. Старые `file_id` не меняются автоматически; перед заменой проверяйте новый файл через `/material_verify`.

Откат к прежнему коду — возврат на предыдущий локальный коммит. Данные новых таблиц остаются безвредными: миграция аддитивная и не затрагивает старые таблицы/бота.
